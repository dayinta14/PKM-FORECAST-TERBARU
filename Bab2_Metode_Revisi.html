2. Research Method

2.1 Research Framework

This study adopts a hybrid predictive modelling approach that integrates classical statistical time-series analysis with a deep-learning architecture. Following Zhang (2003), the framework decomposes the stock price series $Y_t$ into a linear component $L_t$ and a nonlinear residual component $N_t$ through the additive decomposition:

$$Y_t = L_t + N_t \tag{1}$$

An essential design principle of this framework is that each ticker is modelled independently. No single pooled model is built across all four equities; instead, separate ARIMA orders are identified, separate LSTM weights are trained, and separate evaluation metrics are computed for ADRO, PTBA, INDY, and ITMG. This stock-specific approach is justified by the substantial heterogeneity in price levels, volatility structure, and autocorrelation patterns across the four companies, as demonstrated in the descriptive statistics and stationarity tests in Section 3.1. Pooling the series into a single model would conflate fundamentally different data-generating processes and invalidate the assumptions of each component model.

The overall research workflow proceeds through the following sequential stages: (i) data acquisition and preprocessing; (ii) stationarity testing; (iii) ARIMA fitting and residual extraction; (iv) LSTM residual learning; (v) hybrid combination; (vi) out-of-sample evaluation against multiple benchmarks including a Naïve Random Walk; and (vii) exploratory long-term scenario generation. All stages are implemented in Python and documented in the accompanying source files (model_arima.ipynb, model_ann_lstm.py, expanding_window_cv.py).

2.2 Research Data and Dataset Split

The primary data consist of daily Adjusted Closing Price series for four Indonesian coal-sector equities listed on the Indonesia Stock Exchange (IDX): ADRO, PTBA, INDY, and ITMG. Data were retrieved from Yahoo Finance via the yfinance API on 31 December 2024, covering the period 1 January 2004 – 31 December 2024, yielding 5,199 trading-day observations per ticker after holiday imputation. The raw series are stored in harga_saham_batubara.csv.

Forecast Horizon and Prediction Mechanism

Model evaluation on the test set is conducted using a one-step-ahead rolling forecast (recursive rolling-origin scheme). At each time step $t$ in the test period, the ARIMA component generates a one-step-ahead forecast using all data up to $t-1$, and the LSTM component predicts the corresponding residual using a sliding window of the 30 most recent residual observations ending at $t-1$. The actual observed value $y_t$ is then incorporated into the history before the next step, so that each forecast conditions exclusively on information available prior to the prediction point. This design eliminates look-ahead bias and mirrors realistic production forecasting conditions.

Implementation Environment

All experiments are executed using Python 3.11, TensorFlow 2.21.0 / Keras, statsmodels 0.14, scikit-learn 1.4, pandas 2.2, numpy 1.26, and yfinance 0.2. A global random seed of 2024 is set at the start of every script (np.random.seed(2024) and tf.random.set_seed(2024)) to ensure full reproducibility. The hardware environment consists of an Intel Core i7-12700H processor, 16 GB RAM, and an NVIDIA RTX 3060 GPU (CUDA 12). All dependency versions are documented in requirements.txt, and source code, trained model weights, and derived data files are maintained in the project repository.

2.3 Data Preprocessing

2.3.1 Missing Value Handling

Trading-day gaps arising from public holidays are imputed using a sequential forward fill followed by backward fill:

$$Y_t = Y_{t-1} \quad \text{if } Y_t \text{ is missing} \tag{2}$$

2.3.2 Stationarity Testing

Stationarity is assessed using a complementary dual-test strategy: the Augmented Dickey-Fuller (ADF) Test and the Kwiatkowski-Phillips-Schmidt-Shin (KPSS) Test. The null hypothesis of the ADF test is the presence of a unit root ($H_0$: non-stationary), while the KPSS test has stationarity as its null. Agreement between both tests reduces the risk of a Type I or Type II classification error.

All four series are found to be integrated of order one, I(1): non-stationary at the price level but stationary after first-order differencing ($d = 1$). A special case arises with ADRO: although the ADF test rejects the unit-root null at the first-difference level (ADF statistic $= -11.91$, $p < 0.001$), the KPSS statistic on the first-differenced series remains marginally above the 5% critical value (KPSS $= 0.756$), indicating residual non-stationarity of a different form, possibly heteroscedasticity. In practice, $d = 1$ is retained for ADRO because the log-return series is confirmed stationary by both tests; the ARIMA model is estimated on first-differences, consistent with the standard convention for financial price series. This issue is acknowledged as a potential source of estimation uncertainty in the ADRO model.

First-order differencing is defined as:

$$\Delta Y_t = Y_t - Y_{t-1} \tag{3}$$

2.3.3 Min-Max Scaling

Prior to LSTM training, the residual series is transformed to the interval $[0, 1]$ to facilitate gradient-based optimisation:

$$X_{\text{scaled}} = \frac{X - X_{\min}}{X_{\max} - X_{\min}} \tag{4}$$

Scaling parameters are estimated exclusively from the training partition and stored in scalers_resid.pkl; the same parameters are applied to the test partition, precluding information leakage from future observations.

2.3.4 Sliding-Window Sequence Construction

The scaled residual series is transformed into supervised learning pairs $(\mathbf{x}, y)$ using a sliding window of length $k = 30$ trading days:

  • Input: $\mathbf{x}_t = [\epsilon_{t-k},\, \epsilon_{t-k+1},\, \dots,\, \epsilon_{t-1}]$
  • Target: $y_t = \epsilon_t$

This window length is consistent with approximately one calendar month of trading days and is held constant across all folds and all tickers.

2.4 ARIMA Modelling and Residual Extraction

2.4.1 Linear Component: ARIMA$(p,d,q)$

The ARIMA$(p,1,q)$ model captures the linear dynamics of the differenced price series:

$$\Phi_p(B)(1-B)^d Y_t = \Theta_q(B)\epsilon_t \tag{5}$$

The ARIMA order $(p,1,q)$ is determined independently for each ticker through an exhaustive grid search over $p,q \in \{0,1,2,3,4\}$ (25 combinations per ticker), selecting the specification that minimises the Akaike Information Criterion (AIC). The value $d = 1$ is fixed for all tickers based on the stationarity test results in Section 2.3.2. Models are estimated using statsmodels.tsa.statespace.SARIMAX with the L-BFGS-B solver (maximum 300 iterations). For the expanding-window cross-validation (Section 2.8), the grid search is repeated independently within each fold's training window, so that the selected order does not carry information from future sub-periods.

2.4.2 Residual Extraction

After fitting ARIMA on the training data, the in-sample residuals $\hat{\epsilon}_t$ are extracted as the difference between the observed price and the ARIMA fitted value:

$$\hat{\epsilon}_t = Y_t - \hat{L}_t, \quad t \in \text{Training Set} \tag{6}$$

These residuals represent the portion of the price series that cannot be explained by the linear ARIMA structure and constitute the target sequence for LSTM training. Leading NaN values arising from the differencing operation are discarded before passing the residual sequence to the LSTM.

2.4.3 Residual Diagnostic: Ljung–Box Test

To confirm that the extracted residuals are suitable targets for nonlinear learning — i.e., that no significant linear autocorrelation remains — the Ljung–Box portmanteau test is applied at lags $h \in \{5, 10, 20\}$:

$$Q_h = n(n+2)\sum_{k=1}^{h}\frac{\hat{\rho}_k^2}{n-k} \tag{7}$$

where $\hat{\rho}_k$ is the sample autocorrelation at lag $k$ and $n$ is the effective sample size. A $p$-value greater than 0.05 at all tested lags indicates that the residual series is free of significant linear serial dependence, confirming that the ARIMA has adequately captured the linear structure and that any remaining signal in $\hat{\epsilon}_t$ is of a nonlinear character amenable to LSTM modelling.

2.5 LSTM Residual Modelling

2.5.1 Architecture

The LSTM network processes the residual sequence $\hat{\epsilon}_t$ through the following architecture, implemented in model_ann_lstm.py and expanding_window_cv.py (function build_lstm, lines 58–69):

  1. Input layer: sequence of shape $(30, 1)$
  2. LSTM layer 1: 64 units, return_sequences=True
  3. Dropout: rate $r = 0.20$
  4. LSTM layer 2: 64 units
  5. Dropout: rate $r = 0.20$
  6. Dense layer: 32 units, ReLU activation
  7. Output layer: 1 unit, linear activation

The gating mechanism of each LSTM cell is governed by:

$$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f) \tag{8}$$
$$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i) \tag{9}$$
$$C_t = f_t \odot C_{t-1} + i_t \odot \tanh(W_c \cdot [h_{t-1}, x_t] + b_c) \tag{10}$$
$$h_t = o_t \odot \tanh(C_t) \tag{11}$$

2.5.2 Training Protocol and Leakage Prevention

Training data are fed to the network in their original chronological order; no shuffling is applied. The last 15% of the training sequence is withheld as an in-training validation set (validation_split = 0.15) to monitor generalisation and trigger early stopping. Because this split is taken from the tail of the training window — i.e., the most recent 15% of the pre-2023 data — it remains temporally prior to the test set and introduces no future leakage.

Two callbacks govern the training process:

  • EarlyStopping: monitors val_loss, patience = 15 epochs, restores best weights.
  • ReduceLROnPlateau: halves the learning rate when val_loss stagnates for 5 consecutive epochs.

The model is compiled with Adam optimizer ($\eta = 0.001$, batch_size = 32) minimising mean squared error (MSE). The global random seed (SEED = 2024) is set before every model instantiation to ensure reproducibility.

2.6 Hybrid ARIMA-LSTM Combination

The final hybrid prediction is constructed by linearly combining the ARIMA linear forecast $\hat{L}_t$ with the LSTM residual estimate $\hat{\hat{\epsilon}}_t$:

$$\hat{Y}_t = \hat{L}_t^{\text{ARIMA}} + \hat{\hat{\epsilon}}_t^{\text{LSTM}} \tag{12}$$

On the test set, $\hat{L}_t^{\text{ARIMA}}$ is obtained from arima_model.get_forecast(steps=1) at each rolling step, and $\hat{\hat{\epsilon}}_t^{\text{LSTM}}$ is the inverse-scaled output of the trained residual LSTM given the 30 preceding residual observations. Inverse transformation is performed using the scaler fitted on the training residuals (scalers_resid.pkl), ensuring that scale restoration is consistent across all steps and that no test-set statistics influence the transformation.

2.7 Model Evaluation and Performance Measurement

2.7.1 Benchmark Models

Four models are compared in the out-of-sample evaluation:

The Naïve Random Walk serves as the primary benchmark. Under the weak-form Efficient Market Hypothesis, stock prices approximate a random walk, implying that any forecasting model must outperform this naïve forecast to demonstrate genuine predictive skill. MASE and RMSSE (defined below) are normalised against the random walk's one-step-ahead absolute error, providing a scale-free performance comparison across the four tickers whose price levels differ by an order of magnitude.

2.7.2 Evaluation Metrics

All metrics are computed on the aligned test set of 446 observations per ticker. The first 30 observations of the 476-point test window are consumed as the initial LSTM input sequence (window $k = 30$), consistent with the implementation in hitung_r2_lstm.py (lines 32–34: N_TEST = 476, WINDOW = 30, N_EVAL = 446).

1. Mean Absolute Error (MAE)

$$\text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i| \tag{13}$$

2. Root Mean Squared Error (RMSE)

$$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2} \tag{14}$$

3. Mean Absolute Percentage Error (MAPE)

$$\text{MAPE} = \frac{100\%}{n}\sum_{i=1}^{n}\left|\frac{y_i - \hat{y}_i}{y_i}\right| \tag{15}$$

4. Coefficient of Determination ($R^2$)

$$R^2 = 1 - \frac{\displaystyle\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}{\displaystyle\sum_{i=1}^{n}(y_i - \bar{y})^2} \tag{16}$$

A negative $R^2$ indicates that the model performs worse than a constant forecast equal to the historical mean $\bar{y}$, which may arise during out-of-sample periods characterised by structural breaks or distributional shift relative to the training period.

5. Mean Absolute Scaled Error (MASE)

$$\text{MASE} = \frac{\text{MAE}}{\dfrac{1}{n-1}\displaystyle\sum_{t=2}^{n}|y_t - y_{t-1}|} \tag{17}$$

MASE normalises the absolute error against the mean absolute one-step-ahead naïve forecast error. A value less than 1 indicates that the model outperforms the Naïve Random Walk.

6. Root Mean Squared Scaled Error (RMSSE)

$$\text{RMSSE} = \sqrt{\frac{\text{RMSE}^2}{\dfrac{1}{n-1}\displaystyle\sum_{t=2}^{n}(y_t - y_{t-1})^2}} \tag{18}$$

RMSSE is the quadratic counterpart of MASE, penalising large individual errors more heavily and providing a scale-free comparison across equities with different price levels.

7. Directional Accuracy (DA)

$$\text{DA} = \frac{1}{n-1}\sum_{t=2}^{n}\mathbf{1}\!\left[\text{sign}(y_t - y_{t-1}) = \text{sign}(\hat{y}_t - \hat{y}_{t-1})\right] \times 100\% \tag{19}$$

DA measures the proportion of time steps for which the model correctly predicts the direction (upward or downward) of price movement. This metric is particularly relevant for practitioners concerned with directional trading signals rather than the magnitude of the forecast error alone.

2.8 Expanding-Window Cross-Validation

Prior to the final evaluation on the 2023–2024 test set, model stability is assessed using an expanding-window cross-validation scheme implemented in expanding_window_cv.py. Three folds are defined as follows:

The mean MAPE across three folds provides a temporally robust estimate of predictive performance that is less susceptible to the idiosyncrasies of any single evaluation sub-period.

2.9 Exploratory Long-Term Scenario Generation (2025–2045)

The best-performing model per ticker — selected on the basis of the 2023–2024 out-of-sample evaluation — is used to generate exploratory price scenarios for January 2025 through December 2045 using an iterative recursive multi-step forecast: the model produces one-step-ahead predictions sequentially, and each predicted value is appended to the input history before the next prediction step.

Important disclaimer: These long-term projections are conditional scenarios, not validated forecasts. The model assumes structural stability over a 20-year horizon, whereas empirical evidence suggests that financial markets undergo periodic regime changes. Forecast uncertainty accumulates with each recursive step, producing progressively widening confidence bands. No out-of-sample evidence exists to validate 20-year projections against observed outcomes. Accordingly, the projections are presented as exploratory methodological illustrations under a ceteris paribus assumption and must not be interpreted as investment recommendations.

Ninety-five percent confidence intervals for the long-term scenarios are derived from the ARIMA component's get_forecast() method, which propagates forecast error variance analytically:

$$\hat{Y}_t^{\text{lower}} = \hat{L}_t - 1.96\,\hat{\sigma}_e(h), \qquad \hat{Y}_t^{\text{upper}} = \hat{L}_t + 1.96\,\hat{\sigma}_e(h) \tag{20}$$

where $\hat{\sigma}_e(h)$ denotes the estimated standard error at forecast horizon $h$, which increases with $h$ to reflect the accumulation of prediction uncertainty inherent in multi-step recursive forecasting.

2.10 Interactive Web Dashboard

Model outputs — including historical prices, test-set predictions, evaluation metrics, and long-term scenarios — are integrated into an interactive web-based analytical dashboard implemented in HTML5, Vanilla CSS3, JavaScript ES6+, and Chart.js v4.4.2 (index.html). The dashboard provides per-ticker navigation, KPI cards displaying MAE, RMSE, MAPE, R², a train/test/forecast zone chart, and a scenario projection table covering milestone years 2025–2045. The dashboard is deployed publicly via Netlify to facilitate broad dissemination of the research outputs.

The dashboard serves exclusively as a visualisation and dissemination interface; it does not perform any model computation and is therefore considered a complementary output distinct from the forecasting methodology itself. A scenario disclaimer is prominently displayed within the dashboard to prevent misinterpretation of the long-term projections as validated predictions.
